**미믹·현장 대역 기준이다.** 현장 플릿 대역의 인수 확인은 앞 세대로 통과한 변경이 없으면 곧바로 `DURABLE_CONFIRMED` 로 답한다 — `DURABLE_PENDING` 과 그 재시도(기본 1초)는 이 표에 나오지 않는다. 플릿 세계는 하네스가 가상 시계를 밀지 않아 운반이 `ACCEPTED` 에 선 채다. 실 플릿 벤더 API 에는 이 인수 확인이 없다.

## 회차

플릿 전용 작업 지시(DeliverContainer, `OUT-07` → `LINE-IN-03`, 용기 `HU-1042`, 기체 단위 없음) 하나를 내고 현장 플릿이 맡은 뒤, 첫째 호스트를 멈춤·리스 반환 없이 죽이고 곧바로 둘째를 띄운다. 둘째가 관측(`HOLDING`)에 든 것을 보자마자 운반 취소를 건다(운영자 확인 없음) — 취소는 플릿 준비가 서야 플릿에 나간다. 리스 설정마다 세 회차.

- «플릿 확인»: 둘째의 `GET /host/leader` 의 `readiness.fleet.reasonCode` 가 `RECONCILING`(확인됨 — 재대조 대기)이 된 것을 본 때.
- «준비»: `readiness.fleet.ready` 가 참이 된 것을 본 때(확인 경계 뒤에 보낸 플릿 읽기로 재대조 → 근거 커밋 → 래치).
- «첫 플릿 수락»: 현장 플릿 세계에서 그 운반이 `CANCELLED` 가 된 것을 본 때.
- 위 셋은 하네스가 50 ms 마다 읽은 JVM 시각(죽임 기준)이다. «리빌드 완료»·«근거 커밋» 은 DB 시각(리스 만료 기준)이다. 두 시계를 섞지 않는다.
- «잠금 조회» 는 측정 구간 동안 호스트 잠금을 쓰는 조회(`GET /host/executions/summary`)를 50 ms 마다 부른 지연이다 — pump·잠금 점유를 직접 재지 않은 대리 지표다.
- «STALE(플릿)» 은 현장 플릿 면이 세대로 거절한 수, «밀려남» 은 둘째가 잃은 수, «해제» 는 준비가 선 뒤 다시 풀린 것을 본 수다.

## 읽기

- 리빌드 완료 → 플릿 근거 커밋은 77~1384 ms(DB). 확인은 리스를 얻은 직후(재대조·관측 진입과 같은 때) 잠금 밖 확인 스레드가 한 번 부르고, 재대조는 그 뒤 pump 앞의 다시 읽기 라운드다. 첫 HOLDING pump 의 라운드는 앞 pump 가 물은 것이 없어 그 pump 가 처음 묻는 플릿 읽기(복원한 운반의 상태)를 다시 읽지 못해 온전하지 않고, 다음 라운드는 재대조 라운드 간격(`HostFleetPort.ROUND_GAP`, 1초) 뒤에야 돈다 — 그래서 확인 관측 → 준비 관측이 28 ms 인 회차(첫 라운드가 온전)와 1.25~1.38 초인 회차(한 라운드 더)로 갈린다. 라운드 간격 도입 전에는 둘째 회차가 다음 pump(250 ms)에서 끝나 460~560 ms 였다.
- 준비 관측 → 첫 플릿 수락 관측은 231~264 ms. 준비가 선 다음 pump 에서 취소가 잠금 밖 송신으로 나가고, 그 결과를 다음 라운드가 받는다 — pump 주기 하나 남짓과 하네스 읽기 주기가 더해진 값이다.
- 죽임 → 첫 플릿 수락은 리스 만료 폭(30초·3초)에 0.3~1.7초가 더해진 값이다. 바탕에서는 이 자리가 운영자 확인까지의 사람 시간이었다.
- 플릿 확인 호출은 준비까지 한 번이었고(현장 대역이 곧바로 확정), 세대 거절·밀려남·해제는 0 이다. 인수 뒤 상태는 모두 `HOLDING`·발행 표시 거짓 — 플릿 운반은 운영자 확인 없이 나갔지만 전역 발행·새 접수는 그대로 닫혀 있다.
- 잠금 조회 지연 p95 는 1.6~3.9 ms, 최대 8.8~182 ms 다. 확인 HTTP 는 잠금 밖이고 재대조의 다시 읽기도 pump 앞(잠금 밖)에서 하므로 잠금 아래에 플릿 HTTP 왕복이 들지 않는다. 최대값은 복원·근거 커밋이 든 pump 와 겹친 몇 번이다(대리 지표라 pump 점유 자체는 아니다).
- `DURABLE_PENDING`(실제 수신자의 정리 대기)·현장 재시작(기동 ID 변경)·옛 현장은 이 표 밖이다 — 그때는 재시도 간격(1초)마다 다시 묻거나 운영자 확인을 기다린다(시험: `FleetReadinessTest`·`FleetReadinessHostTest`).
